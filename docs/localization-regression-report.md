# 本地化回归检查报告（2025-11-01）

## 检查目标

确认近期将命令行输出汉化为中文后，是否对 OpenSpec 项目的正常运行造成影响，并识别需要调整的测试或其他依赖。

## 执行环境

- 操作系统：Windows（PowerShell 默认 shell）
- Node 包管理器：pnpm v10.15.0（项目中存在更新提示，但未升级）

## 检查步骤

1. `pnpm install`
2. `pnpm test`

## 主要发现

- **字符串断言失效**：绝大多数断言仍假设英文提示，例如 `Nothing to show.`、`Skipping spec updates`、`Tool summary:` 等。现在命令实际输出已翻译成中文，例如 `没有可显示的内容。`、`跳过规范更新`，导致断言不再成立。
- **国际化策略缺失**：当前实现直接将原有英文常量替换为中文，尚未提供语言切换或多语言资源管理。测试、自动化脚本或第三方集成只要依赖旧的英文输出，将立即失效。
- **命令行为未出现功能性错误迹象**：从失败日志看，除字符串比较外，命令流程（如归档、初始化、更新）仍照常执行，说明逻辑路径大体正常。但仍需人工确认是否存在遗漏翻译或乱码。
- **跨平台测试用例提醒**：`test/commands/spec.test.ts` 中使用 `cat` 命令比较文件内容，在 Windows 环境本身无法执行，与本次汉化无关，但会继续导致此测试失败。

## 风险评估

- **高**：所有依赖英文提示文本的测试套件与自动化流程需要同步调整，否则无法通过 CI/CD。
- **中**：用户文档、变更说明等若仍引用英文提示，需要更新以保持一致。
- **低**：核心业务逻辑未见异常，但仍建议补充手动冒烟测试以覆盖关键 CLI 命令。

## 建议与下一步工作

1. **更新测试基线**：将断言调整为当前中文输出；或引入可配置的语言资源，允许测试固定在某种语言上。
2. **规划多语言支持**：考虑通过 i18n 资源文件管理提示文本，避免未来再次全量替换导致大面积断言回归。
3. **补充文档**：在 README 或变更日志中注明默认语言已改为中文，并提示如何切换（若未来提供选项）。
4. **验证关键用例**：对 `openspec init`、`openspec update`、`openspec validate` 等命令进行手动核对，确认输出内容完整、无截断或格式异常。
5. **CI 调整**：在测试流程未更新前，可临时将相关测试标记为预期失败或跳过，以保证流水线可用，但不建议长期保持。
