# OpenSpec 汉化版快速开始指南

## 🎯 5 分钟快速上手

### 第一步：安装汉化版

⚠️ **重要**：不要使用 `npm install -g @fission-ai/openspec`！

```bash
# 1. 进入 OpenSpec 汉化版目录
cd d:\AI\openspec

# 2. 构建并全局链接
pnpm install && pnpm build && npm link

# 3. 验证（应该看到中文）
openspec --help
```

### 第二步：初始化项目

```bash
# 1. 进入你的项目
cd your-project

# 2. 初始化 OpenSpec
openspec init

# 3. 选择 AI 工具（如 Auggie）
# 4. 填写 openspec/project.md
```

### 第三步：创建第一个变更

```bash
# 在 AI 工具中（如 Auggie）
/openspec-proposal 添加用户搜索功能

# 或自然语言
"请创建 OpenSpec 提案，添加用户搜索功能"
```

### 第四步：实施变更

```bash
# 在 AI 工具中
/openspec-apply add-user-search

# 或自然语言
"请实施 add-user-search 变更"
```

### 第五步：归档变更

```bash
# 部署后归档
openspec archive add-user-search --yes
```

## 📚 核心概念

### 三阶段工作流

```
创建提案 → 实施变更 → 归档变更
    ↑                        ↓
    └────────────────────────┘
         （循环：下一个功能）
```

### 目录结构

```
your-project/
├── AGENTS.md                    # 引导 AI 使用 OpenSpec
├── openspec/
│   ├── project.md               # 项目上下文
│   ├── AGENTS.md                # AI 工作流指令
│   ├── specs/                   # 当前规范（真相源）
│   │   └── [capability]/
│   │       └── spec.md
│   └── changes/                 # 变更提案
│       ├── [change-id]/
│       │   ├── proposal.md      # 提案说明
│       │   ├── tasks.md         # 任务清单
│       │   ├── design.md        # 技术设计（可选）
│       │   └── specs/           # 规范 Delta
│       │       └── [capability]/
│       │           └── spec.md
│       └── archive/             # 已归档的变更
└── .augment/                    # AI 工具配置
    └── commands/
```

## 🔧 常用命令

### 查看命令

```bash
openspec list                    # 列出活跃变更
openspec list --specs            # 列出所有规范
openspec show <change-id>        # 查看变更详情
openspec show <spec> --type spec # 查看规范详情
```

### 验证命令

```bash
openspec validate <change-id>           # 验证变更
openspec validate <change-id> --strict  # 严格验证
openspec validate --changes             # 批量验证
```

### 归档命令

```bash
openspec archive <change-id>       # 交互式归档
openspec archive <change-id> --yes # 非交互式归档
```

### 管理命令

```bash
openspec init      # 初始化项目
openspec update    # 更新 AI 指令
```

## 💡 使用技巧

### 何时创建提案？

**需要创建**：
- ✅ 新功能
- ✅ 破坏性变更
- ✅ 架构变更
- ✅ 性能优化（改变行为）

**不需要创建**：
- ❌ Bug 修复
- ❌ 拼写/格式/注释
- ❌ 配置更改

### Slash 命令 vs 自然语言

**Slash 命令**（快捷）：
```
/openspec-proposal <描述>
/openspec-apply <change-id>
/openspec-archive <change-id>
```

**自然语言**（通用）：
```
"请创建 OpenSpec 提案..."
"请实施 <change-id> 变更"
"请归档 <change-id> 变更"
```

### 验证最佳实践

```bash
# 创建提案后立即验证
openspec validate <change-id> --strict

# 实施前再次验证
openspec show <change-id>

# 归档前确认
openspec list
```

## 🚀 完整示例

### 场景：添加用户认证功能

```bash
# 1. 初始化（一次性）
cd my-app
openspec init
# 选择 Auggie
# 填写 openspec/project.md

# 2. 创建提案
# 在 Auggie 中：
/openspec-proposal 添加用户认证功能，支持邮箱密码登录和 JWT

# AI 生成：
# openspec/changes/add-user-auth/
# ├── proposal.md
# ├── tasks.md
# └── specs/auth/spec.md

# 3. 验证提案
openspec validate add-user-auth --strict
openspec show add-user-auth

# 4. 审查并批准
# 阅读 proposal.md, tasks.md, specs/auth/spec.md
# 确认无误后批准

# 5. 实施变更
# 在 Auggie 中：
/openspec-apply add-user-auth

# AI 按 tasks.md 实施：
# ✓ 1.1 创建 User 模型
# ✓ 1.2 添加数据库迁移
# ✓ 2.1 实现注册端点
# ✓ 2.2 实现登录端点
# ✓ 2.3 实现 JWT 生成
# ✓ 3.1 编写单元测试
# ✓ 3.2 编写集成测试

# 6. 测试
npm test
npm run dev
# 手动测试注册和登录功能

# 7. 部署
git add .
git commit -m "feat: add user authentication"
git push
# 部署到生产环境

# 8. 归档
openspec archive add-user-auth --yes

# 输出：
# ✓ 变更 'add-user-auth' 有效
# ✓ 所有任务已完成
# ✓ 规范已更新
# ✓ 变更已归档到 changes/archive/2025-11-01-add-user-auth/

# 9. 验证归档
openspec list
# 输出：未找到活跃的变更。

openspec list --specs
# 输出：
# specs/auth/spec.md

# 10. 查看规范
openspec show auth --type spec
# 显示完整的认证规范
```

## ❓ 常见问题

### Q: 为什么不能用 npm 安装？

**A**: 因为我们对 OpenSpec 进行了汉化改造，npm 上的是英文原版。必须使用本地构建的汉化版。

```bash
# ❌ 错误方式
npm install -g @fission-ai/openspec

# ✅ 正确方式
cd d:\AI\openspec
pnpm install && pnpm build && npm link
```

### Q: 如何更新汉化版？

**A**: 重新构建即可。

```bash
cd d:\AI\openspec
git pull origin zh-cn-lite  # 拉取最新汉化
pnpm build                  # 重新构建
# npm link 会自动使用最新构建
```

### Q: 如何在多个项目中使用？

**A**: 汉化版已全局链接，可以在任何项目中使用。

```bash
# 项目 A
cd project-a
openspec init

# 项目 B
cd project-b
openspec init

# 都使用同一个汉化版
```

### Q: Codex 的配置在哪里？

**A**: Codex 使用全局配置，位于用户主目录。

```
C:\Users\Administrator\.codex\prompts\
├── openspec-proposal.md
├── openspec-apply.md
└── openspec-archive.md
```

所有项目共享这些配置，且已完全汉化。

### Q: 如何验证是汉化版？

**A**: 查看帮助信息。

```bash
openspec --help

# 应该看到中文：
# 用法: openspec [选项] [命令]
# 
# OpenSpec - 为 AI 编码助手提供规范驱动开发
# ...

# 如果看到英文，说明安装了原版
```
